# Logging Strategy

One stream per container (stdout), collected by the platform (Fluent Bit /
Cloud Logging / ELK) and shipped to a central aggregator. No log files in
containers, no log shipping code in the app.

## Format

Controlled by `LOG_FORMAT`:

- `text` (dev): `2026-09-24 10:01:02 schoolos.api INFO [a1b2c3] message`.
- `json` (staging/prod): one JSON object per line —
  `{"ts","level","logger","request_id","msg","exc?"}`.

Set `LOG_FORMAT=json` in every deployed environment so the aggregator can
parse, filter and alert without regex. `LOG_LEVEL` defaults to `INFO`;
`DEBUG` only for short-lived incident sessions.

## Correlation

- Every API request gets an `X-Request-ID` (client-supplied or generated by
  `RequestIdMiddleware`), echoed on the response and attached to every log
  record in scope via `app/core/logging.py`.
- Workers log `request_id: "-"`; execution logs carry `execution_id`,
  `tenant_id`, `user_id` and `language` in the message extras instead.
- Audit rows (`audit_logs`) are the durable record for security events;
  logs are the operational view — join them by `request_id`/timestamp.

## What to log

| Event | Level | Logger |
|---|---|---|
| Request lifecycle (method, route template, status, latency) | INFO | via metrics, not per-request logs |
| Auth denials (401/403 with actor, tenant, ip) | WARNING | `schoolos` (+ audit row) |
| Unhandled exceptions | ERROR (traceback) | `schoolos` |
| Job failures, worker crashes | ERROR | `schoolos.queue` / `schoolos.worker` |
| E-Lab outcomes (status, runtime, backend — never code) | INFO | `schoolos.elab` |
| Migration apply, worker start/stop | INFO | alembic / `schoolos.worker` |
| Quota breaches (429) | WARNING | `schoolos` |

## What must NEVER be logged

Passwords, tokens (access/refresh/select), connection URLs, S3/API keys,
request bodies on auth routes, student source code, stdin, or full file
contents. Code review and the gitleaks CI gate enforce this; treat a secret
in logs as a security incident (rotate + purge retention).

## Retention

- Hot (searchable): 14 days. Warm (compressed): 90 days.
- Audit rows live in PostgreSQL under the normal backup regime, not the
  log pipeline — compliance retention is a database concern.

## Local development

`docker compose logs -f api worker elab-worker` streams text logs with
request ids. To preview production shape, set `LOG_FORMAT=json` in `.env`
and re-create the containers.
